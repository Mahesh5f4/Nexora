# ThinkAction Project - Interview Preparation Guide

This document is your master guide for explaining the ThinkAction AI platform in a technical interview. It covers the core topics you must master, an end-to-end flow of the architecture, and how to pitch your contributions using the STAR (Situation, Task, Action, Result) method.

---

## 📚 1. Core Topics You Must Know

Before walking into an interview, ensure you are comfortable speaking about the following technologies and concepts used in this project:

### Architecture & Backend
- **Microservices vs. Monolith**: Why you chose a split architecture (Spring Boot for Auth/Gateway, FastAPI for AI/ML).
- **Spring Boot Security**: JWT (JSON Web Tokens), stateless authentication, password hashing (BCrypt).
- **Rate Limiting**: How you implemented rate limiting to prevent abuse (e.g., Redis-based token buckets or Spring Boot rate limiters).
- **SSE (Server-Sent Events)**: How SSE differs from WebSockets and why it's perfect for streaming LLM tokens one way from server to client.

### AI & Machine Learning
- **LangGraph**: How stateful, cyclic graphs orchestrate LLM workflows compared to linear chains (LangChain).
- **RAG (Retrieval-Augmented Generation)**: The complete pipeline (Text Chunker → Embedding Model → Vector Store → Similarity Search → LLM Context Injection).
- **Vector Databases (Qdrant)**: How vector DBs use cosine similarity or dot product to find semantically similar text.
- **LLM Function Calling (Tool Use)**: How the agent decides to trigger Web Search or memory retrieval.

### Infrastructure & DevOps
- **Docker & Docker Compose**: How multiple containers (Nginx, Postgres, Redis, Qdrant, Spring Boot, FastAPI) communicate over an internal bridge network.
- **Nginx Reverse Proxy**: Routing `/api/auth` to Spring Boot and `/api/ai` to Python, and the importance of `X-Accel-Buffering: no` for streaming.
- **AWS EC2 Deployment**: Managing cloud instances, security groups (opening port 80/443), and SSH access.

## 🔄 2. End-to-End Flow (Login to AI Response)

When an interviewer asks, *"Walk me through what happens when a user types a message"*, explain it in these exact steps:

1. **Authentication (Spring Boot)**
   - The user submits their email/password to the React frontend.
   - The frontend sends a POST request to `Spring Boot (Auth Service)` via the Nginx proxy.
   - Spring Boot hashes the password, verifies it against PostgreSQL, and generates a **JWT (JSON Web Token)**.

2. **Sending the Message (React to Gateway)**
   - The user types a prompt (e.g., "What is Vector Search?").
   - React opens an **SSE Connection** to `/api/ai/conversations/{id}/messages/stream`, attaching the JWT in the Authorization header.

3. **Gateway Routing & Auth Validation (Nginx & Spring Boot)**
   - Nginx receives the request and forwards it. (If it hits Java first, Java validates the JWT, extracts the User ID, and forwards it to the Python AI service over the Docker internal network).

4. **Agent Orchestration (FastAPI & LangGraph)**
   - **Entry Point**: The Python service initializes an `AgentState` with the user's prompt and past conversation history.
   - **Classification Node**: A heuristic router analyzes the prompt using Regex patterns. It determines if the prompt needs Web Search, RAG, or Memory. (e.g., "What is Vector Search" sets `needs_web=True`).
   - **Routing**: Based on the flags, LangGraph routes execution to `collect_initial_evidence`.
   
5. **Tool Execution (RAG & Web Search)**
   - **Qdrant**: The `RAGService` uses `SentenceTransformer` to embed the query, sends the vector to Qdrant, and retrieves the top 5 most relevant document chunks.
   - **Web Search**: Concurrently, it queries a Web API (like Tavily or DuckDuckGo) for real-time data.

6. **Generation & Streaming (Gemini API)**
   - The retrieved context and web results are injected into a massive system prompt.
   - The prompt is sent to the **Gemini 1.5 Pro** API with streaming enabled.
   - As Gemini yields tokens, FastAPI yields them back to the client using `StreamingResponse`.

7. **Client Rendering (React)**
   - Nginx explicitly has `proxy_buffering off` (or respects `X-Accel-Buffering: no`) so the tokens instantly reach the browser.
   - React appends the tokens word-by-word to the UI without auto-scroll jitter.

## ⭐ 3. Explaining the Project (STAR Method)

When asked about challenges or your proudest achievement on this project, use this script:

### The "Streaming & Nginx Optimization" Story
> **Situation**: "While building the ThinkAction platform, we had a complex polyglot architecture: a Spring Boot auth gateway and a Python FastApi agent service. We needed real-time token streaming for a good AI UX."
> 
> **Task**: "I had to ensure that tokens generated by the Gemini API were streamed word-by-word all the way through Python, through the Nginx reverse proxy, and into the React frontend without lag or chunky buffering."
> 
> **Action**: "I diagnosed that Nginx was silently buffering our Server-Sent Events (SSE). I implemented `X-Accel-Buffering: no` and `Cache-Control: no-cache` headers directly in the Python and Java backend responses. On the frontend, I optimized the React `useEffect` hooks to prevent scroll-yank during high-frequency token updates."
> 
> **Result**: "This completely eliminated the 'chunky' 3-line delays. The platform now streams tokens perfectly in real-time, resulting in a significantly more responsive and premium user experience."

### The "Benchmarking & Resilience" Story
> **Situation**: "Before scaling our platform, we needed empirical data on how our dual-backend architecture and LangGraph agents would handle production load."
> 
> **Task**: "I was tasked with building a complete, reproducible benchmarking suite that evaluated both concurrent load limits and RAG retrieval accuracy."
> 
> **Action**: "I wrote a `k6` load testing script that mocked full user lifecycles (register, login, chat stream) and executed it directly against our AWS EC2 instance. Concurrently, I wrote Python evaluation scripts that bypassed the LLM to directly test our RAG (Recall@K) and LangGraph routing heuristics using deterministic datasets."
> 
> **Result**: "We proved our Qdrant RAG pipeline achieves 100% Recall@5. The load test successfully handled 10 concurrent heavy streaming users flawlessly (6s p95 latency), but actively identified a 25-user threshold where our external LLM provider begins rate-limiting (HTTP 429). This gave us the exact metrics needed to implement a Redis request queue for our next iteration."
